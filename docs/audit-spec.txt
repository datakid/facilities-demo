Your demo already contains the right core idea: **a gate × a weighted score, with every number traceable**. The new product takes that idea and turns it into a tool people can use to build their own models. A few suggestions before the spec:

1. **Don't promise "perfect" equations.** No tool can know what perfect is for someone else's problem. It can show whether a model is robust: how much the weights can move before the winner changes, which criterion decides the result, and which options fail which rules. The sensitivity strip from your demo is the feature that delivers this, so make it central.
2. **Two layers should come from where things appear, not from separate screens.** Simple mode shows a list of criteria with sliders. Clicking one opens an inspector. The Advanced switch adds fields in the same places: expressions, ranges, shape parameters and a custom combine formula. Nothing moves when you switch.
3. **Keep one source of truth.** Everything is a JSON model. The simple UI writes to the same fields the expressions use, so the two modes can't disagree. Export is just printing that model in four formats.
4. **Never use `eval`.** Custom formulas run through a small parser. That also makes it possible to explain every step of a calculation and to generate clean JavaScript for export.
5. **Your demo becomes a starter template, "Care routing",** and the spec has a test that it reproduces the demo's score. That's a good check that Sonnet built the engine correctly.
6. **Leave out of v1:** fitting weights automatically from examples the user ranks by hand, comparing two models side by side, and the cohort simulation. These are good v2 features, and adding them now is how the app gets busy again.

## 1. What the app is

The app is a sandbox for building a scoring equation that ranks a set of options, the rows of a small dataset. The equation is always:

```
Score(row) = Gate(row) × Combine( s₁…sₙ , w₁…wₙ ) × 100
Gate(row)  = 1 if every enabled rule passes, else 0
sᵢ         = Shape( Direction( Normalize( Raw_i(row) ) ) )   ∈ [0,1]
wᵢ         = weightᵢ / Σ weights of enabled criteria
```

Users edit the rules, the criteria (source, direction, shape, weight), the combine method and the data. They can see the ranked result, trace any row step by step and export the model.

## 5. Expression language (expr.js)

API:
```js
M.expr.parse(src)            // -> { ast } or { error:{ msg, pos } }
M.expr.check(ast, names)     // names: Set of allowed identifiers -> null or { msg, pos }
M.expr.evaluate(ast, scope)  // scope: plain object; returns number (booleans as 1/0) or string
M.expr.idents(src)           // -> array of {name, start, end} from tokens (for rename)
M.expr.rename(src, old, neu) // token-exact replacement, preserves user formatting
```

Tokens are numbers (`12`, `1.5`, `.5`, `1e3`), identifiers, double-quoted strings, operators `+ - * / % ^ ( ) , < <= > >= == != && || !`, and whitespace. Anything else is `"Unexpected character"` at its position.

Grammar (recursive descent, lowest precedence first):
```
or    := and ( "||" and )*
and   := cmp ( "&&" cmp )*
cmp   := add ( ("<"|"<="|">"|">="|"=="|"!=") add )?
add   := mul ( ("+"|"-") mul )*
mul   := unary ( ("*"|"/"|"%") unary )*
unary := ("-"|"!") unary | pow
pow   := atom ( "^" unary )?          // right-associative: 2^3^2 = 512
atom  := number | string | "true" | "false" | ident | ident "(" args? ")" | "(" or ")"
```
AST nodes: `{t:'num',v}`, `{t:'str',v}`, `{t:'id',name,pos}`, `{t:'un',op,a}`, `{t:'bin',op,a,b}`, `{t:'call',fn,args,pos}`.

Functions (fixed list): `min(…)`, `max(…)`, `abs(x)`, `sqrt(x)`, `exp(x)`, `ln(x)`, `log10(x)`, `pow(a,b)`, `clamp(x,lo,hi)`, `if(cond,a,b)`, `round(x)`, `round(x,n)`. A wrong argument count gives `"clamp needs 3 values"`.

Semantics:
1. Comparisons and logic return 1 or 0.
2. Strings are only allowed on either side of `==` or `!=`. Anywhere else is the runtime error `"Text can only be compared"`.
3. An identifier whose scope value is `null` gives the runtime error `"Missing value: price"`.
4. If `evaluate` throws, the engine catches it. A non-finite result counts as invalid.

## 6. Shapes (shapes.js)

Every shape takes `t ∈ [0,1]` and returns `s ∈ [0,1]`:
```
linear : s = t
curve  : s = t^k                           k ∈ [0.25,4], default 2   (k>1 strict, k<1 lenient)
scurve : σ(x)=1/(1+e^(−a(x−c)));  s = (σ(t)−σ(0))/(σ(1)−σ(0))   a ∈ [2,30] default 10, c default .5
step   : s = t >= c ? 1 : 0                c default .5
target : s = exp(−((t−c)/width)²)          c default .5, width ∈ [.05,1] default .2   (ignores direction)
map    : category columns only; s = map[value] ?? 0, values in [0,1]
```
Export `M.shapes.apply(shape, t)` and `M.shapes.META` (labels, parameter lists with min, max and step, and one plain-English line each):
- linear: "Straight line"
- curve: "Bends toward strict or lenient"
- scurve: "Soft cut-off around a point"
- step: "Full points past a line, none before"
- target: "Best at a sweet spot"
- map: "Points per category"

## 7. Engine (engine.js)

`M.engine.compute(model)` is pure. It returns:
```js
{ ranges:{ [critId]:{lo,hi,auto} },
  weights:{ [critId]: share },            // normalized, sums to 1 over enabled criteria with weight>0
  rows:[ { id,label, pass, gates:[{id,pass,error}], failReason,
           crit:{ [critId]:{ raw, t, s, w, contrib, error } },
           S, score, rank } ],             // rank null if !pass
  ranked:[rowId...], out:[rowId...],
  lead:{ winner, runnerUp, margin, driver:{critId, pts} } | null,
  errors:[ { where:'gate'|'criterion'|'combine', id, msg, pos } ] }
```
Pipeline, in exactly this order:
1. **Parse and check** every enabled gate expression, criterion `expr` source and custom combine expression once. Allowed names: gates and criterion sources may use column ids and param ids. A custom combine may use criterion ids (their `s`), `w_<critId>` (their share) and param ids. Anything that fails to parse or check goes into `errors`. That item is treated as disabled for this computation, and the UI shows the error.
2. **Gates:** evaluate per row with scope = row values + params. `pass` = all enabled gates are 1. If there's a runtime error, the gate fails and `error` holds the message. `failReason` = the label of the first failing gate, or its expr if it has no label.
3. **Raw values:** evaluate per row for every row, including rows that fail a gate. A `boolean` column becomes 1 or 0.
4. **Range per criterion:** if `auto`, use the min and max of valid raw values over all rows, including failed ones, so that rules don't shift other rows' scores. Otherwise use `lo` and `hi`. Skip this for `map`.
5. **Normalize:** `t = clamp((raw−lo)/(hi−lo), 0, 1)`. If `hi===lo`, then `t = 0.5`, and the inspector shows "Every row is equal here, so this criterion has no effect." If direction is `lower` and the shape isn't `target`, use `t = 1−t`.
6. **Shape:** `s = shapes.apply`. If raw is invalid or missing, set `s = 0` and store `error`.
7. **Weights:** `share_i = weight_i / Σ weight over enabled criteria`. If the sum is 0, every score is 0 and the result area shows "Give at least one criterion some weight."
8. **Combine:**
   - sum: `S = Σ share·s`, with `contrib = share·s`
   - product: `S = Π s^share`
   - min: `S = min s` over enabled criteria with share > 0
   - custom: evaluate the expression. If `S` is outside [0,1], don't clamp it; add a warning to `errors`.
9. `score = pass ? S·100 : 0`. Round only when displaying (one decimal).
10. **Rank:** passing rows by score descending, ties broken by label ascending. Failing rows go in `out`, ordered by label.
11. **Lead** (sum mode only, when at least 2 rows are ranked): `margin = score₁ − score₂`. The driver is the criterion with the largest `(contrib_winner − contrib_runnerUp)·100`.

`M.engine.trace(model, result, rowId)` returns an ordered array of plain lines for the inspector, e.g. `{kind:'raw', critId, text:'price = 899'}`, then `norm`, `dir`, `shape`, `weight`, `gate`, `combine` and `final`. Each line has a `value` field for the number to display.

## 8. Sensitivity (sensitivity.js)

`M.sensitivity.sweep(model, critId)` runs for `v = 0..100` step 1:
1. Set the weight of `critId` to `v`.
2. Scale the other enabled weights proportionally so they sum to `100−v`. If they're all zero, split `100−v` equally.
3. Compute and record the winner id (or null).
4. Collapse the results into runs `[{from, to, winner}]` and return `{runs, current: currentShare×100}`.

Only run it when Advanced is on, debounced by 150 ms after the last change.

## 9. Codegen (codegen.js)

`M.codegen.js(model, result)` returns a string. Build it from the ASTs, never by pasting source text. Map identifiers like this:
- column → `r.<id>`
- param → `P.<id>`
- criterion in combine → `s.<id>`
- `w_<id>` → `W.<id>`

Function calls go to `F.<name>`, and strings go through `JSON.stringify`. Auto ranges are baked in as literals, with the comment `// auto range from current data`. Required output shape:

```js
// Meridian model: "<name>" · generated <ISO date>
const P = { lambda: 40 };
const W = { price: 0.3, battery_h: 0.25 };
const F = { min:Math.min, max:Math.max, abs:Math.abs, sqrt:Math.sqrt, exp:Math.exp,
  ln:Math.log, log10:Math.log10, pow:Math.pow, round:(x,n=0)=>Math.round(x*10**n)/10**n,
  clamp:(x,a,b)=>Math.max(a,Math.min(b,x)), if:(c,a,b)=>c?a:b };
const norm = (x, lo, hi) => hi === lo ? 0.5 : F.clamp((x - lo) / (hi - lo), 0, 1);
/* only the shape helpers this model uses */
export function score(r) {
  if (!(r.price <= 1800)) return { pass: false, score: 0, s: {} };
  const s = {};
  s.price = 1 - norm(r.price, 749, 1999);
  s.battery_h = norm(r.battery_h, 8, 20);
  const S = W.price * s.price + W.battery_h * s.battery_h;
  return { pass: true, score: S * 100, s };
}
```

`M.codegen.formula(model)` returns Unicode plain text: the main equation, then one line per criterion (`Price = linear(1 − norm(price, 749…1999))`) and one line per rule.
